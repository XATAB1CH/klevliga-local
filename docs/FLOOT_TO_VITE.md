# Floot → VS Code → Vite: план миграции

## Реальная отправная точка

Floot = текущая платформа разработки; это **не Flutter**. Нынешний интерфейс уже React/TypeScript и CSS Modules. Экспортированный архив Floot — Node.js/Vite-ориентированное приложение со своим рантаймом. Не предполагать, что это готовый `react-ts` шаблон; заглянуть в README архива.

## Скачивание

- В браузере открыть Floot → проект «КлёвЛига — UX/UI главной» → название проекта → Get Code → Download as ZIP.
- На платном тарифе доступен также Get Code → Folder Sync (Chrome/Edge), но для ухода в VS Code/Git удобнее ZIP.
- В ZIP **нет** файлов, размещённых во Floot Storage. Скачать картинки из Storage отдельно; пути вида `/_cdn/static/xxx.png` не будут работать на localhost. Не полагаться на эти URLs в продакшене.
- Если платного экспорта нет, исходники можно прочитать покомпонентно, но это не равнозначно полному архиву.

## Порядок работы с Codex

1. Распаковать ZIP в `exports/floot-original` (папку не изменять, хранить как эталон), в отдельном рабочем репозитории создать `apps/web`.
2. Сначала локально запустить **оригинальный экспорт** по его README; зафиксировать, какие страницы и изображения отображаются.
3. Создать Vite `react-ts` в `apps/web` (`npm create vite@latest apps/web -- --template react-ts`) с актуальным Node.js. Установить `react-router-dom`, `lucide-react`, прочие зависимости по импортам. Не копировать все Floot-дизайн-примеры и не брать бэкенд Floot.
4. Перенести `pages/_index.tsx`, `pages/_index.module.css`, `pages/v2*.tsx`, `pages/v2.module.css`, `components/V2Layout.*`, нужные `Button`, `Input`, `Textarea` и их CSS в `src`. Перенести `base.css` и глобальные шрифты/переменные.
5. Создать `src/app/router.tsx` с маршрутами:
   - `/` — MVP главная;
   - `/v2` — концепт 2.0 главная;
   - `/v2/community` — сообщество;
   - `/v2/waters` — карта водоёмов;
   - `/v2/water` — карточка водоёма;
   - `/v2/assistant` — ИИ-помощник;
   - `/v2/market` — барахолка;
   - `/v2/profile` — профиль.
6. Перенести изображения в `apps/web/public/images/`, заменить Floot-specific `/_cdn/static/...` на `/images/...` в `ASSETS`, `v2img`. Убедиться, что права на каждый снимок позволяют использовать его на сайте.
7. Проверить `npm run dev`, `npm run build`, работоспособность кнопок, ссылок, фильтров и модалок.
8. После визуального parity — вынести общие UI-компоненты, сервисы, API hooks и убрать демо-костыли. Не делать крупных редизайнов одновременно с миграцией.

## Стартовая инструкция для Codex

> Ты ведущий frontend-инженер. В этом репозитории есть `exports/floot-original` с экспортом сайта «КлёвЛига» и `api/openapi.yaml`. Перенеси визуальный интерфейс на `apps/web` (Vite + React + TypeScript + CSS Modules). Сохраняй стили, цветовую палитру, фотографии, шрифты и адаптивную мобильную версию 1:1. Не создавай Go backend и не подключай новые сервисы. Сначала проанализируй экспорт и напиши план и список импортов/зависимостей; затем перенеси главную `/`, установи зависимости и добейся чистого `npm run build`. После этого перенеси страницы `/v2/*`. Убери Floot-specific импорты, если они присутствуют; все действия UI должны продолжать работать с моковыми данными. Поставь тесты smoke для навигации и открытий модалок. Покажи список изменённых файлов, команды запуска и ограничения.

## Caveats

- `server.ts` из экспортированного Floot-приложения предназначен для его self-host режима и **не нужен** внутри Vite SPA после завершения миграции.
- Экспортированный Floot сам не гарантирует SSR/SEO; для публичного форума продумать это до запуска.
- Не коммитить `.env`, `env.json` с реальными ключами, JWT secrets и пользовательские дампы данных.
